# TS1201 ZHA 试点版安装与维护

适用精确指纹 `TS1201 / _TZ3290_qazgdsae`，版本1.3.0。当前交付面向工程人员部署和有限客户试点；普通客户的日常使用见 [使用指南](ts1201_customer_guide.md)。本目录是公司维护的自定义试点方案，不代表官方 ZHA 已原生提供这些界面。

## 安装前

已验证目标环境为 Python 3.14.6、Home Assistant 2026.8.0、zha 2.1.0、zha-quirks 2.2.0、zigpy 2.1.0。先确认设备接入目标 ZHA 实例，或准备在安装后配对。本安装器不负责配对、发码或重启。

先通过 Home Assistant 的备份功能建立完整备份。安装器只备份本包管理的代码与码库；它不备份或改写 `zigbee.db`、`.storage`、用户 YAML、凭据或其他自定义 quirk。按键库、已确认码库和实体注册信息的灾难恢复，需要完整 HA 备份。

从本公司仓库下载完整源码 ZIP（仓库页面 Code → Download ZIP），解压后保留目录结构；也可以使用内容与本仓库同版本一致的完整 TS1201 交付包。不要只下载单个 Python 文件来安装完整面板。仓库根目录下的 `TS1201_BUNDLE_MANIFEST.json`、`zemismart_ts1201_ir_zha.py`、`data/`、`custom_components/ts1201_ir/` 和 `scripts/` 必须一起保留。安装器只复制清单列出的 16 个 TS1201 文件，不安装仓库中其他设备的 quirk。清单用于发现文件缺失或损坏，不是发布者数字签名。

## 检查和安装

安装器使用 Python 标准库。**在实际运行 Home Assistant 的 Python 环境执行**，这样才能检测真实的依赖版本。SSH 附加组件通常有独立 Python，不能用它的包版本代替 HA Core 环境。

以下示例将解压后的仓库根目录重命名为 `ts1201-release`，放在 HA 配置目录中；`/config/ts1201-release/` 应直接包含上述清单和 `scripts/`，不要多嵌套一层仓库目录。安装器默认以自身的上一级目录为交付根目录。在 HA Core 容器内部执行：

```sh
python /config/ts1201-release/scripts/ts1201-install.py check --config-dir /config
python /config/ts1201-release/scripts/ts1201-install.py install --config-dir /config
```

使用容器安装、且当前终端能访问 Docker 的工程人员，可在上面两条命令前加 `docker exec homeassistant`；容器名和实际配置挂载路径应以该实例为准。HA OS 的普通终端不一定具有容器管理权限，不能直接套用其他实例的 SSH 命令。

`check` 只读检查完整性、目标目录、版本、待更新文件、未完成事务和安装锁状态。存在未完成事务时，先恢复原事务，再进行升级，避免将混合版本作为新备份基线。`install` 在全部预检通过后备份受管旧文件，再写入新文件；写入失败时尝试恢复并报告具体结果。默认阻止未知或未验证的运行时组合。`--allow-unverified-runtime` 仅供工程人员在独立测试环境验证新版本，不是客户兼容性保证，也不会跳过文件和路径检查。

配置中应有下面的 ZHA 设置；安装器不自动修改它。有现有 `zha:` 块时合并进去，不要创建第二个同名块。使用其他 quirk 路径的实例应先由工程人员统一路径，不能安装到未加载的目录后声称生效。

```yaml
zha:
  enable_quirks: true
  custom_quirks_path: /config/zha_quirks
```

确认配置有效后，在 HA 界面重启 Home Assistant。配套集成的 Python 模块更新需要进程重新加载，单纯复制文件或重载 ZHA 不等于更新完成。首次安装时，再到“设置 → 设备与服务 → 添加集成”，添加 `TS1201 IR Remote / TS1201 红外遥控器`。

## 安装后验收

- 目标 ZHA 设备诊断匹配完整厂家和型号，选中本 quirk；关联设备为“TS1201 红外遥控器”。
- 界面已有的实体 ID 和用户命名保留；空键库名称栏为空白，状态提示引导先命名再学习。暂不适用的管理入口收进禁用列表，需要时自动恢复。此类管理实体只在适用时可调用，日常自动化应使用保存后的命名按钮或空调实体。
- 升级和重启不会自动重发红外。已确认码库与已有设置恢复；页面是命令估计，不是空调状态回传。
- 单独验收原遥控器学习、确认保存、按钮发送、家电响应，以及保存后 HA 重启和红外盒断电恢复。软件测试不能替代这一步。

HA 可能在管理入口恢复启用后自动短暂重载配套集成。软件回归已覆盖学习中和完整捕获待保存两个阶段：保留状态且不额外发码；这不替代现场学习验收。

若客户自行禁用某个实体，集成不会擅自启用它。自动恢复仅限本集成因操作暂不适用而禁用的实体。

## 回滚

成功安装会返回备份标识。保留该标识和 `/config/.ts1201-backups/` 下对应目录。回滚使用安装输出中的实际标识：

```sh
python /config/ts1201-release/scripts/ts1201-install.py rollback --config-dir /config --backup-id '<安装返回的备份标识>'
```

回滚前验证备份及当前受管文件；如果安装后文件被其他人修改，会停止并报告冲突，避免覆盖后来工作。回滚只恢复这次受管文件变更，不恢复系统数据库。若回滚中途遇到读写错误，先不要重启 HA；修复该错误后使用同一个备份标识重试，工具会跳过已经恢复的文件。完整回滚成功后再重启 HA 并核实版本和控件。不要在学习或发送过程中升级、回滚或重启。

## 安装被中断后的恢复

如果安装进程被终止或报告恢复失败，先运行 `check` 查看原事务及锁状态。不要删除事务清单、重新生成旧备份的哈希，或直接开始第二次安装。

```sh
python /config/ts1201-release/scripts/ts1201-install.py recover --config-dir /config --backup-id '<原事务标识>'
```

`recover` 使用原事务逐项核对内容和权限，将已经写入的新文件恢复至原版本；已恢复文件可安全重试。仍有进行中的安装或文件已被其他人修改时，会停止并说明冲突。恢复成功后重新检查，再决定升级或重启 HA。

若中断发生在生成事务清单之前，仅遗留安装锁，按 `check` 的说明使用不带 `--backup-id` 的 `recover` 清理该锁。旧1.2版的空锁没有进程归属信息；工程人员确已确认旧安装进程结束后，可显式添加 `--confirm-legacy-stale-lock`。该参数不能覆盖新安装器识别出的活跃进程锁。

该恢复流程已验证进程强制终止和读写失败，尚未完成主机突然断电的故障注入；异常断电仍需依靠完整HA备份恢复，不把进程测试视作断电验收。

工具使用 `.ts1201-install.guard` 与带归属信息的安装锁协调安装和恢复；这些是工具自身的维护文件。手工历史备份目录保留不变。对于旧1.2版曾误报 `failed_restored` 的事务，可以明确指定其原备份标识恢复；遇到后来修改的文件仍会停止，不会盲目覆盖。
